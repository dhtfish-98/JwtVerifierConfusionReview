# 验证边界

1. 调用方先确定资源服务信任的 `issuer`、`audience` 和本地公钥集合。策略构造时校验 RSA 密钥强度，并复制为不可变映射；后续调用方修改原字典不改变验证器。
2. 未验证的令牌只用于**有限解析**：校验三段、严格 base64url 与 UTF-8 JSON、重复键、字段集合及固定算法/类型。`kid` 只能选择该策略已持有的密钥；`jku/jwk/x5u/x5c/crit/b64` 均在未知标头阶段拒绝。
3. 使用 PyJWT 对已选 RSA 公钥按硬编码 `algorithms=["RS256"]` 验签，并由库核对到期、未生效时间、签发时间、发行者和受众。其后确认库解码结果与严格解析的声明一致。
4. 资源服务入口只返回统一的 401 或 200；内部拒绝代码仅进入无秘密的本地测试收据。

限制：仅支持本项目的平面 JSON、单字符串受众、固定 RS256 和 `at+jwt`；这不是完整 RFC 9068/JWT 实现。`jti` 被要求为非空标识，但未持久化，因此**不防重放**；没有密钥撤销、外部 JWKS、JWT 授权范围或业务许可检查。实验中的弱基线由本项目故意编写，仅在 `tests/`，不代表依赖或第三方服务的缺陷。
